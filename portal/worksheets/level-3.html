2. 철학자 API 사례로 흐름 이해하기

교사가 제공·관리하는 API 주소를 사용할 때의 예시입니다. 학생은 API 키를 받거나 HTML에 넣지 않습니다.

학생의 질문→내 웹 화면→교사 관리 API→철학자 원문 검색→답변 + 참고 근거

3. API를 사용할 때의 주의사항

비밀키·개인정보·근거를 함께 점검합니다.

  • API 키, 관리자 비밀번호, 비공개 주소를 GitHub·HTML·학습지에 적지 않습니다.
  • 실명, 연락처, 건강·위기 정보 등 민감한 개인정보를 질문으로 보내지 않습니다.
  • AI 답변과 검색된 원문 근거를 구분합니다. 근거가 있어도 답변 전체가 사실이라고 단정하지 않습니다.
  • 철학자 말투는 심리치료나 진로·의학·법률 결정을 대신하지 않습니다.
  • API가 멈추거나 자료가 오래되었을 때의 기준 날짜와 대체 안내를 둡니다.

4. 자주 묻는 질문

왜 HTML에 API 키를 넣으면 안 되나요?

웹페이지를 열 수 있는 사람은 소스에서 키를 확인할 수 있습니다. 키는 서버 환경변수로만 관리합니다.

검색 근거가 있으면 답변은 모두 맞나요?

아닙니다. 근거의 날짜·맥락·범위를 사람이 다시 확인해야 합니다.

API 오류가 나면 프로젝트 실패인가요?

아닙니다. 오류를 감지하고 사용자에게 재시도·대체 행동을 안내하는 것도 완성 기준입니다.

대화 기록은 어디에 남나요?

브라우저·서버 중 어디에 얼마나 저장되는지 미리 안내하고, 필요 없는 기록은 보내지 않습니다.
