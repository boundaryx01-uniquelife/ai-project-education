학생 개인 키로 직접 연결하는 흐름

1. API 고르기

자동승인 여부, 서비스 URL, 필수 요청값, JSON 응답 예시를 확인합니다.

2. 개발키 신청

본인 계정으로 개발계정 활용신청을 하고, 키가 발급된 것을 확인합니다.

3. 문서에서 시험

공공데이터포털의 API 설명서·실행 도구로 요청값과 응답을 먼저 읽습니다.

4. 앱에서 직접 요청

키를 실행 중 입력하고, 출처·확인 시각·오류 상태가 있는 결과 화면을 만듭니다.

개발키 규칙: 키 값은 HTML·JavaScript·GitHub 저장소·GitHub Pages·제출 화면 캡처에 넣지 않습니다. 실습 중 개인 입력칸에만 넣고, 노출이 의심되면 포털에서 삭제·재발급합니다. 정적 웹에서 직접 요청하면 브라우저 네트워크에 키가 보일 수 있으므로 수업용 개발키로만 연습합니다.

AI에 보내는 실제 요청 예시

부산 생활 데이터 앱 · 직접 API 연결 요청COPY
부산 생활필수품 가격 정보를 이용하는 웹앱을 만들어줘. 공공데이터포털 API 설명서의 서비스 URL, 필수 요청값, JSON 응답 항목을 먼저 확인해줘. 사용자는 품목 또는 조건을 입력하고, 앱은 결과를 카드로 보여 준다. 정상 결과, 검색 결과 없음, API 연결 오류를 각각 분명하게 보여줘. 출처와 데이터 확인 시각을 결과 카드 아래에 표시해줘. 개인 개발키는 실행 중 password 입력칸에서만 받고, HTML·JavaScript·localStorage·GitHub 저장소·배포본에 절대 저장하지 마. 개발키가 비어 있으면 호출하지 말고 입력 방법을 안내해줘. 바뀐 파일의 전체 코드를 파일명별로 나누어 출력해줘.

FAQ와 수업 전 확인 사항

개인 개발키를 앱에 직접 넣어도 되나요?

실행 중 입력칸에서 이번 실습에만 넣는 것은 가능합니다. 다만 정적 웹의 요청 URL은 브라우저에서 보일 수 있으므로, 키를 코드·저장소·배포본에 넣어 공개하면 안 됩니다. 운영 서비스용 키 관리는 Level 4의 서버 환경 주제입니다.

자동승인인데 API 호출이 실패해요.

승인 상태, 서비스 URL, 필수 요청값, JSON 옵션, 일일 호출 한도를 문서에서 순서대로 확인합니다. 브라우저에서 CORS 오류가 난다면 그 API는 이 수업의 직접 호출 대상으로 적합하지 않을 수 있습니다. 다른 자동승인 API로 바꾸거나 API 문서의 실행 도구에서 응답 구조를 먼저 연습합니다.

교사 중계 서버는 전혀 쓰지 않나요?

기본 실습에서는 쓰지 않습니다. 키를 숨긴 공개 서비스 운영, 사용량 통제, 여러 API의 응답 형식 통일이 필요할 때만 교사가 선택하는 심화 운영 방식입니다.

부산 실시간 버스 도착 정보도 첫 프로젝트로 가능한가요?

흥미로운 심화 주제지만 정류소·노선 식별, 응답 구조, 호출 조건을 함께 다뤄야 합니다. 자동승인·CORS·문서 상태를 수업 직전에 확인한 뒤, 첫 프로젝트는 입력이 더 단순한 가격·업소·도로 정보 API로 시작하는 편이 좋습니다.

이 페이퍼는 참고용입니다. 실제 개발키 입력과 직접 요청은 Level 3 따라하기 실습에서 진행합니다.
