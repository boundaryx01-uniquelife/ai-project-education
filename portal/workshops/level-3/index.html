Level 3는 학생이 공공데이터포털에서 직접 개발키를 신청하고, API 설명서를 읽어 요청을 만들고, 실제 응답을 사용자에게 이해되는 정보로 바꾸는 과정입니다.

오늘의 결과물개인 개발키 → 직접 API 요청 → 상태별 결과 화면키는 실행할 때만 입력하고 코드·저장소·배포본에는 남기지 않습니다.

STEP 01

부산 생활 데이터를 직접 고릅니다.

‘개발단계 자동승인’인 OpenAPI를 먼저 선택합니다. 각자 공공데이터포털에 로그인해 개발계정 활용신청을 하고, API 설명서의 서비스 URL·필수 요청값·응답 항목을 읽습니다.

즉시 시작 후보

자동승인 OpenAPI 3개

  • 부산 생활필수품 가격 정보 ↗
  • 부산 착한가격업소 메뉴 정보 ↗
  • 부산 구간통행속도 정보 ↗

다음 행동: API 설명서를 바탕으로 실제 결과 화면을 AI에 요청합니다.

STEP 02

키를 코드에 넣지 않는 화면을 요청합니다.

먼저 예시 데이터로 정상·빈 결과·오류 화면을 만듭니다. 실제 연결 단계에서는 키를 실행 중 입력받고, 소스 코드나 GitHub Pages에 저장하지 않는다는 조건을 반드시 넣습니다.

AI에 보낼 요청
개인 개발키 규칙
직접 쓰되, 남기지 않습니다.
  • 공공데이터포털에서 본인 개발키를 직접 신청한다.
  • 키는 실행 중 입력칸에만 넣고 코드·Git·화면 캡처에는 넣지 않는다.
  • 브라우저 요청에도 키가 보일 수 있으므로 수업용 개발키만 쓴다.
  • 키가 노출되면 삭제·재발급하고, 공개 배포본에서는 비워 둔다.
다음 행동: 내 개발키와 서비스 URL로 한 번 직접 호출합니다.


    
STEP 03
내 개발키로 API를 직접 호출합니다.
공공데이터포털 상세 화면에서 서비스 URL을 복사해 넣습니다. 키는 이 입력칸에서만 사용하며, 이 페이지는 키를 저장하지 않습니다. API마다 검색 요청값 이름이 다르므로 설명서에 맞게 적습니다.
개인 API 요청
키와 서비스 URL은 이 페이지에 저장되지 않습니다.
주소에 이미 필수 요청값이 있다면 그대로 붙여 넣고, 키·검색어만 이 화면에서 더합니다.
학생이 보는 결과
DATA STATUS
아직 데이터를 요청하지 않았습니다.
정상 결과, 검색 결과 없음, 연결 오류를 각각 확인해 보세요.
다음 행동: 세 가지 상태와 출처·확인 시각을 검사합니다.


    
STEP 04
데이터가 없거나 실패할 때도 설명합니다.
외부 데이터는 멈추거나 비어 있을 수 있습니다. 실패를 숨기는 대신 사용자에게 이유와 다음 행동을 알려 주는 것이 Level 3의 완성 기준입니다.
API CONNECTION NOTE
나의 연결 기록
데이터 이름, 문서 주소, 서비스 URL, 요청값, 결과 항목, 오류 처리 방법을 기록합니다. 개발키 값 자체는 기록하지 않습니다.
여기까지 오면 Level 3의 최소 데이터 앱을 완성했습니다.공개 배포 전에는 입력칸·소스·저장소에 개발키가 남아 있지 않은지 다시 확인하세요. CORS를 허용하지 않는 API는 문서의 테스트 도구로 먼저 검증하고, 수업 기본 과정에서는 다른 직접 호출 가능 API로 바꿉니다.
연결 규칙과 API 목록은 PROJECT PAPER에서 다시 확인할 수 있습니다.
