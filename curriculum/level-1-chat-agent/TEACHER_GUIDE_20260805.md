# LEVEL 1 교사용 진행안

- 과정: 근거 기반 수업 프로젝트 설계 미니 에이전트
- 시간: 180분
- 대상: 채팅형 AI 기본 사용 경험이 있는 교육자
- 수업 형태: 예시 따라하기 + 선택형 변형

## 수업 전 준비

### 교사 준비물

- 통합 교육포털 접속 주소 또는 로컬 사본
- 기준 예시 자료 3건
- 실패 사례용 가짜 출처 1건
- 학습자 결과 저장 폴더 또는 문서
- 채팅형 AI 접속 환경

### 자료 준비 원칙

- 자료 3건은 같은 주제를 서로 다른 관점에서 다뤄야 한다.
- 한 자료는 적용 가능성이 낮거나 조건이 제한적이어야 한다.
- 출처, 작성 주체, 작성일과 원문 위치를 확인할 수 있어야 한다.
- 학생 개인정보가 포함된 실제 사례는 사용하지 않는다.

## 구간별 진행

### 0. 비교 체험, 0~15분

교사는 같은 문제에 대해 두 방식의 결과를 보여준다.

- 방식 A: 한 문장으로 수업안 전체 생성
- 방식 B: 문제 정의, 자료 비교, 구조 설계, 테스트를 거친 결과

질문:

- 어떤 결과가 수정하기 쉬운가?
- 어떤 결과가 근거를 확인하기 쉬운가?
- 다른 주제로 다시 사용할 수 있는 것은 어느 쪽인가?

핵심 메시지는 `좋은 프롬프트`가 아니라 `검증 가능한 작업 구조`를 만드는 것이다.

### 1. DEFINE, 15~40분

학습자는 프로젝트 브리프를 작성한다.

필수 항목:

- 사용자
- 해결할 문제
- 사용 장면
- 수업 시간 또는 운영 제약
- 성공 조건
- 하지 않을 범위

교사는 문제가 지나치게 크면 `한 번의 수업에서 사용하는 한 가지 도구` 수준으로 축소시킨다.

체크포인트:

- 사용자가 실제로 존재하는가?
- 결과물을 사용할 장면이 분명한가?
- 성공 여부를 확인할 수 있는가?

### 2. COLLECT + STRUCTURE, 40~70분

학습자는 자료 3건을 다음 기준으로 비교한다.

- 출처와 작성 주체
- 핵심 주장
- 적용 대상
- 사용할 수 있는 근거
- 제한 또는 충돌
- 에이전트가 인용할 항목

이후 입력·처리·출력을 설계한다.

교사는 자료 요약만 하지 말고 `이 자료를 어떤 판단에 쓸 것인가`를 질문한다.

### 3. BUILD, 70~115분

학습자는 에이전트 카드를 작성하고 단계별 채팅 명령을 만든다.

권장 처리 단계:

1. 입력 점검
2. 자료 분석
3. 자료 비교
4. 수업 설계
5. 근거·위험 점검
6. 최종 출력

교사는 한 번에 모든 작업을 요청하는 긴 프롬프트보다 각 단계의 목적과 출력 형식을 분리하게 한다.

중간 점검:

- 필수 입력이 없을 때 질문하거나 중단하는가?
- 자료와 AI 추론을 구분하는가?
- 최종 출력에 근거 부족 표시가 있는가?

### 휴식

수업 환경에 따라 BUILD 전후에 10분 휴식을 배치할 수 있다. 총 180분을 유지하려면 공유 시간을 조정한다.

### 4. TEST, 115~145분

세 가지 테스트를 실행한다.

- 정상 입력
- 일부 조건이 빠지거나 충돌하는 경계 입력
- 가짜 출처 또는 개인정보가 포함된 실패 입력

학습자는 예상 결과, 실제 결과, 문제점, 수정 내용을 기록한다.

교사는 결과의 문장 품질보다 다음을 본다.

- 중단해야 할 때 중단했는가?
- 없는 근거를 만들지 않았는가?
- 부족한 입력을 표시했는가?

### 5. PUBLISH, 145~165분

학습자는 공유 패키지를 만든다.

포함 항목:

- 에이전트 이름과 한 줄 설명
- 대상 사용자
- 준비할 입력
- 사용 순서
- 복사용 Context Packet
- 결과 확인 체크리스트
- 알려진 제한
- 버전과 작성일

### 6. IMPROVE, 165~180분

2인 1조로 서로의 에이전트를 실행한다.

동료는 다음만 기록한다.

- 시작하기 어려웠던 점 1개
- 잘 작동한 점 1개
- 위험하거나 모호한 점 1개

학습자는 한 가지 이상을 수정하고 변경 이유를 남긴다.

## 시간 부족 시 축소 순서

다음 순서로 축소한다.

1. 전체 발표를 갤러리 보기로 변경
2. 자료 비교 기준을 6개에서 4개로 축소
3. BUILD 단계의 선택 기능을 제외

다음은 축소하지 않는다.

- 문제 정의
- 출처 기록
- 테스트 3종
- 수정 기록

## 교사의 개입 기준

교사는 정답을 대신 만들지 않고 범위를 줄이고 누락을 발견하게 돕는다.

즉시 개입하는 경우:

- 실제 학생 개인정보 입력
- 출처 없는 자료를 사실로 사용
- 3시간 안에 불가능한 범위
- 단일 프롬프트 복사로 활동 종료
- 실패 테스트를 생략하려는 경우

## 수업 종료 확인

- 모든 학습자가 공유 패키지를 저장했는가?
- 테스트 기록과 수정 전후가 남아 있는가?
- 서로 다른 결과물이 생성되었는가?
- 학습자가 자신의 작업 흐름을 설명할 수 있는가?
