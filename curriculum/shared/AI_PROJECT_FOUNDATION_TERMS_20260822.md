# AI 프로젝트를 시작하기 전에 알아둘 말

AI로 프로젝트를 만들 때는 어려운 기술 이름을 많이 아는 것보다, **AI가 프로젝트 안에서 어떤 일을 맡는지** 구별하는 일이 먼저입니다.

이 자료는 이후 해커톤, 프로젝트 수업, MVP 제작 활동에서 공통으로 참고합니다. 읽고 난 뒤에는 다음 질문에 답할 수 있으면 됩니다.

- 내가 만든 것은 일반 웹앱일까, AI Agent일까?
- 챗봇과 Agent는 무엇이 다를까?
- PWA, MVP, Agent는 각각 무엇을 말할까?

---

## 1. AI가 들어가면 모두 Agent일까?

아닙니다. AI가 있다고 해서 모두 Agent는 아닙니다.

다섯 단계를 구분하는 핵심 질문은 이것입니다.

> **“AI가 어디까지 스스로 판단하고 행동하는가?”**

| 구분 | 사용자가 하는 일 | AI가 하는 일 | 다음 행동을 바꾸는가? | 학생 생활 예시 |
| --- | --- | --- | --- | --- |
| 일반 웹앱 | 정해진 값을 입력한다. | 없다. | 아니다. | 급식 잔반량을 입력하면 합계와 그래프를 보여 준다. |
| AI 웹앱 | 질문이나 내용을 입력한다. | 답변·요약·문장을 만든다. | 보통 아니다. | “우유팩은 어디에 버려?”라고 물으면 분리배출 방법을 설명한다. |
| AI Workflow | 자료나 문장을 입력한다. | 정해진 순서대로 여러 작업을 한다. | 정해진 순서는 바뀌지 않는다. | 문장 입력 → 비속어 검사 → 바른 표현 만들기 → 결과 출력 |
| AI Agent | 질문보다 **목표와 상황**을 준다. | 필요한 일을 판단하고 여러 단계를 처리한다. | 상황에 따라 달라질 수 있다. | 시험일·현재 실력 → 부족 과목 판단 → 우선순위 → 학습 계획 |
| Agentic AI | 목표와 현재 진행 상황을 준다. | 결과를 확인하고 다음 계획을 다시 조정한다. | 그렇다. | 행사 준비 상태 확인 → 부족 작업 판단 → 일정 조정 → 다시 확인 |

한 줄로 보면 이렇게 달라집니다.

```text
정해진 기능 실행
→ AI에게 질문
→ 정해진 순서로 AI 사용
→ 목표를 보고 AI가 판단
→ 결과를 확인하며 다시 판단
```

### 실제로 생각해 보기

`학교 행사 추천 에이전트`라는 이름을 붙였다고 Agent가 되는 것은 아닙니다.

- 행사 아이디어를 하나 추천해 주기만 하면: **AI 웹앱**일 수 있습니다.
- 학생 수, 예산, 준비 기간을 보고 가능한 행사를 고른다면: **AI Agent**에 가까워집니다.
- 준비 상황을 다시 확인하고 계획을 고친다면: **Agentic AI**에 가까워집니다.

## 2. 챗봇과 Agent는 무엇이 다를까?

> **“챗봇은 ‘대답하는 AI’이고, 에이전트는 ‘일을 맡아서 처리하는 AI’다.”**

Agent가 챗봇보다 무조건 더 똑똑하다는 뜻은 아닙니다. 두 도구가 맡는 일이 다릅니다.

| 챗봇 | Agent |
| --- | --- |
| 질문을 받는다. | 목표를 받는다. |
| 답을 만든다. | 필요한 일을 판단한다. |
| 한 번의 질문과 응답이 중심이다. | 두 단계 이상의 처리를 할 수 있다. |
| 설명이나 아이디어를 준다. | 실제로 사용할 수 있는 결과를 만든다. |

### 같은 주제, 다른 역할

**챗봇에게 묻기**

```text
시험 공부는 어떻게 해야 해?
```

챗봇은 공부 방법을 설명할 수 있습니다.

**Agent에게 목표 주기**

```text
시험이 3주 남았고 수학이 부족해.
평일에는 하루 90분, 주말에는 3시간 공부할 수 있어.
내가 확인하며 수정할 수 있는 학습 계획을 만들어 줘.
```

Agent는 다음과 같은 일을 나누어 처리할 수 있습니다.

```text
현재 상태 확인
→ 부족한 과목 판단
→ 시간 배분
→ 날짜별 계획 작성
→ 사용자가 확인할 결과 출력
```

핵심 질문은 이것입니다.

> **“답을 했는가?”가 아니라 “목표를 받아 일을 처리했는가?”**

---

## 3. 이건 Agent일까?

내 프로젝트를 보면서 아래를 체크해 보세요.

- [ ] 사용자가 ‘질문’뿐 아니라 ‘목표’를 주는가?
- [ ] AI가 입력된 상황을 보고 무엇을 해야 할지 판단하는가?
- [ ] 한 번의 답변이 아니라 두 단계 이상의 처리가 있는가?
- [ ] 입력이나 상황이 달라지면 판단과 결과도 달라지는가?
- [ ] 최종적으로 사용자가 실제로 사용할 수 있는 결과가 만들어지는가?

그리고 가장 중요한 질문은 다음입니다.

> **“AI가 스스로 판단한 부분이 어디인가?”**

이 질문에 답하기 어렵다면, 그 프로젝트는 잘못된 것이 아닙니다. 단순 AI 기능이나 AI Workflow일 수 있다는 뜻입니다. 학생 프로젝트에서는 엄격한 이론 판정보다 **내 프로젝트가 어떤 방식으로 작동하는지 설명할 수 있는지**가 더 중요합니다.

## 4. 프로젝트에서 자주 만나는 세 단어

### PWA

**정식 이름:** Progressive Web App

> **“웹으로 만들고, 앱처럼 사용한다.”**

웹 기술로 만들지만 스마트폰이나 컴퓨터에서 앱처럼 사용할 수 있는 웹앱입니다.

예를 들어 학교 분리배출 도우미를 웹으로 만든 뒤, 휴대폰 홈 화면에 설치해 앱처럼 열 수 있습니다.

**꼭 기억할 점:** PWA는 AI의 종류가 아닙니다. 웹앱을 **어떤 형태로 사용하고 제공하는지**에 관한 말입니다.

### MVP

**정식 이름:** Minimum Viable Product

> **“완벽하게 만들기 전에 핵심 기능부터 작동시킨다.”**

아이디어가 실제로 쓸모 있는지 시험하기 위해, 가장 중요한 기능만 먼저 만든 첫 번째 제품입니다.

예를 들어 시험기간 플래너라면 처음부터 회원가입, 알림, 데이터베이스, 공유 기능을 모두 넣지 않습니다.

```text
시험일 입력
→ 과목 정보 입력
→ 학습 계획 출력
```

먼저 이 핵심 기능이 작동하도록 만듭니다.

MVP는 작거나 허술한 프로그램이라는 뜻이 아닙니다. 목적은 다음 과정을 빠르게 반복하는 것입니다.

```text
만들기 → 사용해 보기 → 문제 발견 → 수정하기
```

### Agent

> **“질문에 답하는 것을 넘어 일을 맡아 처리한다.”**

사용자의 목표를 받아 상황을 판단하고, 여러 단계를 거쳐 일을 처리하는 AI입니다.

예를 들어 시험 계획 Agent는 다음처럼 일할 수 있습니다.

```text
시험 날짜 확인
→ 현재 실력 확인
→ 부족한 과목 판단
→ 우선순위 정하기
→ 학습 일정 만들기
```

## 5. PWA, MVP, Agent를 헷갈리지 않기

세 단어는 함께 등장할 수 있지만, 같은 뜻이 아닙니다.

| 용어 | 무엇을 말하는가? | 한 줄로 기억하기 |
| --- | --- | --- |
| MVP | 얼마나 작게 시작하는가 | **시작 방법** |
| Agent | AI가 어떻게 일을 처리하는가 | **AI의 일하는 방식** |
| PWA | 웹앱을 어떤 형태로 사용하는가 | **앱 제공·사용 방식** |

### 하나의 프로젝트에서 함께 만날 수 있는 예

`학습 계획 도우미`를 만든다고 해 봅시다.

- **MVP:** 시험일, 과목, 목표를 입력하면 계획이 만들어지는 핵심 기능만 먼저 만듭니다.
- **Agent:** 학생의 상태를 보고 부족한 과목과 시간 배분을 판단합니다.
- **PWA:** 만든 웹앱을 스마트폰 홈 화면에 설치해 사용합니다.

따라서 `PWA MVP Agent`는 하나의 기술 이름이 아닙니다. 서로 다른 질문에 답하는 세 개의 개념입니다.

## 6. 이제 프로젝트를 시작해 보자

기술 이름보다 먼저 아래 흐름을 생각해 보세요.

```text
문제 발견
→ AI에게 역할 부여
→ 목표 입력
→ AI가 판단·처리
→ 결과 출력
→ 실제 사용
→ 문제 발견
→ 수정
```

처음부터 완성품을 만들 필요는 없습니다.

> **“작동하는 것을 먼저 만들고 직접 사용해 본다.”**

MVP를 만든 뒤에는 무엇이 불편했는지 확인하고, 필요한 기능을 한 가지씩 고칩니다. 이 흐름은 이후 프로젝트의 MVP 제작, 수정·제약, 사용자 검증과 AI 검증, 다음 개발 판단 활동으로 이어집니다.

### 내 문제 찾기 예시

아래는 정답이 아니라 출발점입니다. 같은 구조를 자신의 문제에 적용해 보세요.

| 학생 생활 문제 | 만들 수 있는 아이디어 |
| --- | --- |
| 급식 잔반 줄이기 | 잔반 기록·실천 아이디어 도우미 |
| 학교 분리배출 | 사진·질문 기반 분리배출 도우미 |
| 바른말 사용 | 문장 표현 점검 Workflow |
| 시험 준비 | 학습 계획 도우미 또는 Agent |
| 학교 행사 | 준비 상태를 정리하는 행사 추천 Agent |
| 게임 시간 조절 | 사용 시간 기록·목표 확인 도우미 |
| 용돈 관리 | 지출 기록·목표 점검 웹앱 |

프로젝트의 좋은 시작은 “멋진 기술 이름”이 아니라, **내가 실제로 불편하다고 느끼는 문제 하나**입니다.

## 한 장 요약

```text
일반 웹앱: 정해진 기능을 실행한다.
AI 웹앱: AI에게 질문하고 답을 받는다.
AI Workflow: 정해진 순서로 AI를 여러 번 사용한다.
AI Agent: 목표와 상황을 보고 필요한 일을 판단한다.
Agentic AI: 결과를 확인하고 다음 행동을 다시 조정한다.

챗봇: 대답하는 AI
Agent: 일을 맡아서 처리하는 AI

MVP: 작게 시작하는 방법
Agent: AI의 일하는 방식
PWA: 웹앱을 앱처럼 사용하는 방식
```

다음 활동에서는 이 개념을 바탕으로, 하나의 문제를 골라 실제 MVP를 만들어 봅니다.
