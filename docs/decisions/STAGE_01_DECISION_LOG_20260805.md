# STAGE 01 결정 기록

- 작성일: 2026-08-05
- 단계: 전체 교육과정 체계 설계
- 상태: PROPOSED_FOR_APPROVAL

## D01-01. 주요 교육 대상

1차 대상은 채팅형 AI 사용 경험은 있으나 코딩 경험이 필수적이지 않은 초·중등 교사와 교육 실무자로 한다.

## D01-02. 레벨 구분 기준

LEVEL은 특정 AI 제품이나 코드의 양이 아니라 작업 흐름의 자율성, 자료 연결 범위, 배포 책임과 운영 지속성으로 구분한다.

## D01-03. 공통 생명주기

모든 LEVEL에서 `DEFINE → COLLECT → STRUCTURE → BUILD → TEST → PUBLISH → IMPROVE`를 필수 흐름으로 사용한다.

## D01-04. LEVEL 1

LEVEL 1은 3시간 채팅형 미니 에이전트 과정으로 한다. API 키와 코딩 에이전트 없이 입력·단계·출력·검증 구조를 만든다.

## D01-05. LEVEL 2

LEVEL 2는 4~6시간 배포형 웹 에이전트 과정으로 한다. 제공된 웹 템플릿과 GitHub Pages를 사용하며 핵심 과정은 API 키 없이 작동해야 한다.

## D01-06. LEVEL 3

LEVEL 3는 8~12시간 자료 연결형 에이전트 과정으로 한다. 파일, 공개 데이터, 검색 결과, API 또는 읽기 전용 MCP를 연결하고 출처·최신성·오류를 처리한다.

## D01-07. LEVEL 4

LEVEL 4는 15시간 이상 또는 3~6주 운영형 프로젝트로 한다. 헌장, 역할, 저장소, 테스트, Release, 운영 기록과 핸드오프를 필수로 한다.

## D01-08. 산출물 사슬

모든 과정은 프로젝트 브리프, 자료 기록, 작업 흐름, 제작물, 테스트 기록, 배포 정보와 개선 기록을 연결된 산출물로 남긴다.

## D01-09. 예시와 자유도

권장 비율은 다음과 같이 단계적으로 자유도를 높인다.

- LEVEL 1: 공통 70%, 선택 20%, 자유 10%
- LEVEL 2: 공통 60%, 선택 25%, 자유 15%
- LEVEL 3: 공통 50%, 선택 30%, 자유 20%
- LEVEL 4: 공통 30%, 선택 30%, 자유 40%

## D01-10. 공통 역량

공통 역량은 문제 정의, 자료·근거 활용, 작업 흐름 설계, 컨텍스트 조정, 결과물 제작, 테스트·검증, 배포·재사용, 책임·개선의 8개로 한다.

## D01-11. 평가 방식

평가는 최종 결과물의 외형보다 과정 산출물과 검증 기록을 우선한다. 필수 역량 미통과를 총점으로 상쇄하지 않는다.

## D01-12. 컨텍스트 패킷

모든 과정에서 토큰 절약형 `PROJECT CONTEXT PACKET`과 단계 종료용 `STATE SNAPSHOT`을 공통 형식으로 사용한다.

## D01-13. 기본 도구 범위

정규 기본 과정은 채팅형 AI와 통합 웹포털을 사용한다. Codex, Claude Code, Antigravity와 MCP는 선택형 확장으로 제공한다.

## D01-14. MCP 안전 기준

MCP는 LEVEL 3부터 선택적으로 다루며 읽기 전용 연결부터 시작한다. 권한 확대와 쓰기 작업은 별도 승인 활동으로 분리한다.

## D01-15. 첫 시범 과정

첫 시범 과정은 `근거 기반 수업 프로젝트 설계 미니 에이전트`로 한다. 검색 가능한 환경과 교사가 제공한 자료 묶음 모두에서 운영 가능한 이중 구조로 설계한다.

## D01-16. 단일 포털 원칙

모든 과정은 하나의 통합 포털에 모듈로 추가한다. LEVEL별 별도 저장소와 별도 사이트는 만들지 않는다.
