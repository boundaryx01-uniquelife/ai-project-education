## 이번 수정의 핵심

R02보다 작업 화면의 정보량을 더 줄이고, `샘플을 보고 그대로 따라 만드는 활동`에 집중한다.

## 화면 구조

### 인트로

`index.html`

- 프로젝트 목적 설명
- 에이전트의 간단한 정의
- 초등 / 중·고등 / 성인 선택
- 선택 후 실제 워크숍으로 이동

### 워크숍

`workshop.html?audience=...`

기본 화면은 두 칸만 사용한다.

- 왼쪽 `SAMPLE`: 따라할 예시
- 오른쪽 `FOLLOW`: 내가 작성할 부분

보조 설명은 기본 화면에서 제외하고 접힌 참고 영역으로 둔다.

## 완성 모습 제시

완성 모습을 설명문이나 정적 카드로만 보여주지 않는다.

왼쪽 SAMPLE 상단에 작은 실제 작동 데모를 둔다.

- 초등 용돈지킴이: 용돈·가격·필수지출 입력 → 구매 판단 형태 확인
- 중·고등 시험기간 플래너: 시험일까지 남은 날·공부 시간·과목 입력 → 계획 형태 확인
- 성인 여행 일정 에이전트: 여행 일수·예산·인원·선호 입력 → 일정 형태 확인

미니 데모는 최종 결과물의 사용 경험을 먼저 이해하기 위한 정적 로컬 예시다.

## 따라하기 단계

학습자 화면은 다음 6단계만 보여준다.

1. 목표
2. 판단정보
3. 작동순서
4. 에이전트 생성
5. AI 테스트
6. 완성·개선

내부 교육 생명주기 DEFINE → COLLECT → STRUCTURE → BUILD → TEST → PUBLISH → IMPROVE는 유지한다.

## 만드는 방식 선택 제거

워크숍에서 `예시 체험 / 수정 / 직접 설계` 선택을 다시 묻지 않는다.

인트로에서 고른 대상의 예시를 보고 그대로 따라 만드는 것을 기본 활동으로 한다. 개별화와 커스텀 제작은 LEVEL 1 기본 따라하기를 완료한 뒤 확장 활동으로 제시한다.

## WEB 활동과 AI 활동 구분

모든 단계의 오른쪽 FOLLOW 영역은 두 블록으로 고정한다.

### 웹페이지에서 할 일

- 목표·정보·규칙 작성
- AI 결과 기록
- 최종 패키지 확인

### 생성형 AI에서 할 일

- 현재 단계에 필요한 AI 요청문 확인
- 복사
- ChatGPT·Claude 등에서 실행

두 블록은 색과 제목으로 명확히 구분한다.

AI 상호작용 전용 별도 사이드 패널이나 탭은 사용하지 않는다.

## 최종 결과

마지막 단계에서는 다음을 바로 사용할 수 있어야 한다.

- 최종 에이전트 지침 복사
- 테스트·개선 기록이 포함된 Markdown 패키지 저장

## 완료 확인

각 화면 하단에는 현재 단계의 필수 완료 조건만 간단히 보여준다.

긴 루브릭이나 추가 설명은 작업 화면에 상시 노출하지 않는다.

## 검증 질문

- 첫 화면의 미니 데모가 무엇을 만들지 바로 보여주는가
- 왼쪽 샘플을 보고 오른쪽 작성에 집중할 수 있는가
- 한 화면에서 해야 할 일이 한두 가지로 보이는가
- WEB과 AI 활동을 혼동하지 않는가
- 에이전트 생성과 테스트가 실제 제작 활동으로 느껴지는가
- 최종 지침을 바로 복사해 새 채팅에서 사용할 수 있는가
