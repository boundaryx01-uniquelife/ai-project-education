## 1. 확정된 큰 구조 (4단계)
1. **MVP 제작**
2. **수정·제약**
3. **사용자 검증 + AI 검증**
4. **다음 개발 판단**

## 2. 핵심 원칙
모든 학습자가 동일한 예제를 완성하는 것이 아니라, **공통 제작 방법**을 배운 뒤 각자 자기 문제를 **개별화된 AI 에이전트**로 해결한다. 시험기간 플래너·용돈지킴이·여행 일정 에이전트는 대표 예시일 뿐이며, 최종 과제는 자유주제다.

## 3. 5개 검토 항목 — 최종 결정

| 항목 | 결정 | 잠금 여부 |
|---|---|---|
| 자유주제 허용 시점 | **예시 변형 → 자유주제**를 기본값으로, 연령/숙련도별 진입 시점만 조정 (성인은 1차시부터 자유주제 가능) | 유연 |
| MVP 통과 기준 | 단순 실행 HTML이 아니라 **입력 → 판단 → 출력**이 실제로 작동해야 통과 | **잠금** |
| 수정 단계 요구사항 | 횟수는 제한하지 않되, **제약을 발견해서 고친 수정 최소 1회 이상**을 유형 요건으로 둠 | 유형만 **잠금** |
| 검증 기록 범위 | 사용자 테스트 건수는 유연(최소 1건 권장), AI 의견의 채택/기각 이유 기록 | 이유 기록 잠금 |
| 최종 산출물 형태 | HTML 단독이 아니라 **MVP·수정기록·검증기록·다음 개발판단을 포함한 프로젝트 패키지**로 제출 | **잠금** |

## 4. 단계별 운영 규칙

### 1단계 — MVP 제작
- 통과 기준: 입력 → 정해진 규칙/판단 → 결과 출력이 실제로 보여야 함
- 체크리스트:
  - 입력값을 바꾸면 출력이 실제로 바뀌는가?
  - 그 변화는 미리 정한 규칙/조건에 따른 것인가?
  - 입력을 그대로 되돌려 보여주는 단순 치환은 아닌가?

### 2단계 — 수정·제약
- 최소 1회는 실제 사용 중 발견한 문제 → 수정 형태여야 함
- 버튼 색상 변경 같은 형식적 수정은 인정하지 않음
- 수정 전/후를 간단히 기록

### 3단계 — 사용자 검증 + AI 검증
- 사용자 검증: 본인 또는 동료가 실제 사용 후 피드백 기록
- AI 검증: manual AI-in-the-loop 방식, 선택 사항

> 주의: Claude 원본의 이 부분에는 이전 표현이 남아 있다. 현재 LOCK 기준은 AI 검증 실시 시 채택/기각 및 이유 기록 필수, 생략 시 생략 이유와 대체 검증 기록 필수이다.

### 4단계 — 다음 개발 판단
- 더 개발한다면 무엇을 더할지 판단해서 기록
- 실제 추가 구현은 필수가 아님

## 5. 최종 산출물 패키지
- 최종 HTML 파일
- 수정기록
- 검증기록
- 다음 개발판단

네 가지를 하나의 문서로 묶거나 연령별 워크시트에서 4단계 칸으로 기록할 수 있다.
