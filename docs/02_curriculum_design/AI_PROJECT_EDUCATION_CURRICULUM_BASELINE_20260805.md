# AI 프로젝트 교육과정 기준안

- 작성일: 2026-08-05

- 적용 프로젝트: `ai-project-education`

## 1. 교육과정의 목적

이 교육과정은 AI에게 한 번의 프롬프트로 결과물을 만들게 하는 체험을 넘어, 학습자가 실제 문제를 정의하고 자료를 수집·분석하며 결과물을 제작·검증·배포·개선하는 프로젝트 수행 능력을 기르는 것을 목적으로 한다.

교육 결과는 특정 AI 서비스의 사용법이 아니라 다음의 재사용 가능한 작업 체계여야 한다.

`DEFINE → COLLECT → STRUCTURE → BUILD → TEST → PUBLISH → IMPROVE`

## 2. 주요 교육 대상

### 2.1 1차 대상

- 초·중등 교사, 교육전문직, 교육기관 실무자
- 채팅형 AI의 기본 사용 경험은 있으나 코딩 경험은 필수가 아닌 사람
- 자신의 수업 또는 교육 업무에 적용할 실제 결과물을 만들고자 하는 사람

### 2.2 확장 대상

- 중·고등학생 프로젝트 팀
- 교사 연수 운영자
- 교육용 AI 프로젝트를 설계하는 개발자와 퍼실리테이터

학생 대상 과정은 같은 핵심 체계를 사용하되 언어, 예시, 개인정보 범위와 산출물 난이도를 조정한다.

## 3. 선수 역량

### LEVEL 1

- 채팅형 AI에 입력하고 결과를 복사·수정할 수 있다.
- 브라우저에서 문서와 파일을 다룰 수 있다.

### LEVEL 2

- LEVEL 1을 이수했거나 입력·작업 단계·출력·검증 기준을 가진 미니 에이전트를 설명할 수 있다.
- GitHub 계정을 만들고 제공된 절차를 따라 저장소 또는 Pages 배포를 수행할 수 있다.

### LEVEL 3

- LEVEL 2를 이수했거나 정적 웹 결과물을 배포한 경험이 있다.
- 표, CSV, JSON, 파일 출처와 최신성의 기본 개념을 이해한다.

### LEVEL 4

- LEVEL 3을 이수했거나 자료 연결형 프로젝트를 완성한 경험이 있다.
- 브랜치, 커밋, Issue, 테스트와 Release의 역할을 이해한다.

## 4. 공통 설계 원칙

1. **과정 우선:** 완성 화면보다 문제 정의와 검증 가능한 작업 흐름을 먼저 설계한다.
2. **산출물 사슬:** 모든 단계가 다음 단계에서 사용하는 명시적 산출물을 남긴다.
3. **예시 기반 변형:** 완성 가능한 기준 예시를 따라가되 선택 항목을 통해 결과가 달라지게 한다.
4. **채팅 우선:** 기본 과정은 API 키와 코딩 에이전트 없이 수행 가능해야 한다.
5. **근거와 생성 분리:** 수집한 자료, 분석 결과, AI 생성물과 사람의 최종 판단을 구분한다.
6. **검증 내장:** 정상·경계·실패 사례를 이용한 테스트를 제작 과정 안에 포함한다.
7. **배포와 재사용:** 수업 종료 시 다른 사람이 사용할 수 있는 형태로 정리한다.
8. **플랫폼 독립:** 특정 제품의 현재 UI가 아니라 공통 작업 원리와 파일 형식을 가르친다.

## 5. 단계별 필수 산출물

| 단계 | 핵심 질문 | 필수 산출물 |
|---|---|---|
| DEFINE | 누구의 어떤 문제를 왜 해결하는가? | 프로젝트 브리프 |
| COLLECT | 무엇을 근거로 사용할 것인가? | 자료 목록과 출처 기록 |
| STRUCTURE | 어떤 순서와 형식으로 처리할 것인가? | 작업 흐름도와 입력·출력 정의 |
| BUILD | 사용 가능한 형태로 무엇을 만들 것인가? | 에이전트 카드, 웹 도구 또는 프로젝트 산출물 |
| TEST | 어떤 조건에서 성공하거나 실패하는가? | 테스트 사례와 결과 기록 |
| PUBLISH | 다른 사람이 어떻게 사용할 것인가? | 공유 링크, GitHub 저장소, Release 또는 실행 패키지 |
| IMPROVE | 무엇을 바꾸면 더 나아지는가? | 피드백과 개정 기록 |

## 6. 레벨 체계

| 레벨 | 권장 시간 | 중심 변화 | 대표 결과물 |
|---|---:|---|---|
| LEVEL 1 | 3시간 | 단일 답변에서 단계형 작업 시스템으로 | 채팅형 미니 에이전트 |
| LEVEL 2 | 4~6시간 | 개인 채팅에서 브라우저 기반 공유 도구로 | GitHub Pages 웹 에이전트 |
| LEVEL 3 | 8~12시간 | 생성 중심에서 외부 자료·데이터 근거 중심으로 | 자료 연결형 에이전트 |
| LEVEL 4 | 15시간 이상 | 일회성 제작에서 저장소·테스트·배포·운영으로 | 운영형 장기 프로젝트 |

레벨은 사용하는 AI 제품이나 코드의 양이 아니라 **자료 연결 범위, 자동화 수준, 배포 책임과 운영 지속성**으로 구분한다.

## 7. 시수 구조

### 7.1 LEVEL 1 표준 180분

| 활동 | 시간 |
|---|---:|
| 공통 사례 체험과 목표 확인 | 15분 |
| DEFINE | 25분 |
| COLLECT + STRUCTURE | 30분 |
| BUILD | 45분 |
| TEST | 30분 |
| PUBLISH | 20분 |
| IMPROVE와 공유 | 15분 |

### 7.2 LEVEL 2

- **압축형 240분:** 제공 템플릿 수정, 로컬 확인, GitHub Pages 배포까지 수행한다.
- **표준형 360분:** 사용자 흐름 설계, 결과 내보내기, 예외 처리와 동료 테스트까지 포함한다.

### 7.3 LEVEL 3

- **8시간형:** 제공된 파일 또는 공개 데이터 한 종류를 연결한다.
- **12시간형:** 두 종류 이상의 자료, 출처 표시, 오류 데이터 처리와 읽기 전용 MCP 확장을 포함한다.

### 7.4 LEVEL 4

15시간 이상의 프로젝트 또는 3~6주 스프린트로 운영한다. 헌장, 백로그, 역할, 브랜치, 테스트, Release와 운영 기록을 필수로 한다.

## 9. 수업 환경

- 통합 웹포털은 설명, 예시, 입력 양식, 프롬프트 조립, 체크리스트와 내보내기를 담당한다.
- 채팅형 AI는 자료 분석, 구조화, 생성과 자기 검토를 담당한다.
- GitHub는 공식 저장, 버전 관리와 LEVEL 2 이상의 배포를 담당한다.
- Codex, Claude Code, Antigravity와 MCP는 선택형 확장 활동으로 둔다.

## 10. 토큰 절약 원칙

- 한 번에 하나의 단계만 요청한다.
- 공통 설명은 포털에 두고 AI에는 현재 작업에 필요한 정보만 보낸다.
- 단계가 끝날 때 `확정 결정`, `남은 문제`, `다음 입력`을 짧게 저장한다.
- 원문 전체를 반복하지 않고 출처 번호와 필요한 발췌만 전달한다.
- 새 대화에서도 복원 가능한 컨텍스트 패킷을 사용한다.

## 11. 첫 시범 과정

### 주제

`근거 기반 수업 프로젝트 설계 미니 에이전트`

### 선택 이유

- 모든 교과와 학년에 적용할 수 있다.
- 코딩 없이 공통 생명주기 전체를 경험할 수 있다.
- 검색 가능한 환경과 교사가 제공한 자료 묶음 모두에서 운영할 수 있다.
- 참가자가 교과, 학년, 대상, 자료와 결과물 형식을 바꾸어 서로 다른 산출물을 만들 수 있다.

### 3시간 결과물

- 교육 문제 정의서
- 출처가 기록된 자료 3건 이상
- 자료 비교표
- 입력·작업 단계·출력·검증 기준을 가진 에이전트 카드
- 서로 다른 입력을 사용한 테스트 3건
- 다른 사람이 재사용할 수 있는 공유 패키지

## 12. STAGE 01 완료 조건

- 주요 대상과 선수 역량이 명시된다.
- LEVEL 1~4의 경계가 도구명이 아닌 수행 책임으로 구분된다.
- 각 시수 과정의 필수 산출물과 완료 조건이 정의된다.
- 공통 역량과 평가 모델이 연결된다.
- 컨텍스트 패킷 표준이 마련된다.
- 첫 시범 과정의 주제와 범위가 결정된다.
