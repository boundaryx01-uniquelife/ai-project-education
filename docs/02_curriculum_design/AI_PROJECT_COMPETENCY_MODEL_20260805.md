# AI 프로젝트 교육 공통 역량 모델

- 작성일: 2026-08-05
- 단계: STAGE 01
- 상태: PROPOSED_FOR_APPROVAL

## 1. 목적

이 역량 모델은 학습자가 어떤 AI 제품을 사용했는지가 아니라, 실제 프로젝트를 얼마나 구조적으로 수행하고 근거 있게 검증·배포할 수 있는지를 평가하기 위한 공통 기준이다.

## 2. 공통 핵심 역량

### C1. 문제 정의

사용자, 상황, 문제, 목표와 제한 조건을 구분하고 해결 범위를 현실적으로 설정한다.

### C2. 자료·근거 활용

필요한 자료를 찾거나 제공받아 출처, 최신성, 신뢰도와 활용 가능성을 판단한다.

### C3. 작업 흐름 설계

복잡한 목표를 단계로 나누고 각 단계의 입력, 처리, 출력과 연결 관계를 정의한다.

### C4. 컨텍스트 조정

AI에 필요한 정보만 정확히 전달하고, 확정된 결정과 현재 작업을 분리하여 대화를 관리한다.

### C5. 결과물 제작

프롬프트, 에이전트 카드, 문서, 웹 도구 또는 프로젝트 산출물을 실제 사용 가능한 형태로 만든다.

### C6. 테스트·검증

정상 사례, 경계 사례와 실패 사례를 사용해 결과를 검사하고 근거와 생성 오류를 구분한다.

### C7. 배포·재사용

다른 사람이 이해하고 실행할 수 있도록 사용 방법, 파일, 링크, 버전과 제한 사항을 정리한다.

### C8. 책임·개선

개인정보, 저작권, 편향, 권한과 위험을 점검하고 피드백을 다음 버전에 반영한다.

## 3. 수준별 역량 변화

| 역량 | LEVEL 1 | LEVEL 2 | LEVEL 3 | LEVEL 4 |
|---|---|---|---|---|
| C1 문제 정의 | 제공 양식으로 범위를 정한다 | 사용자 흐름과 기능 범위를 정한다 | 데이터·연결 제약까지 정의한다 | 이해관계자와 운영 범위를 관리한다 |
| C2 자료·근거 | 소수 자료를 비교하고 출처를 남긴다 | 화면·콘텐츠에 근거를 반영한다 | 다중 자료의 최신성·오류를 처리한다 | 출처 정책과 갱신 절차를 운영한다 |
| C3 작업 흐름 | 3단계 이상의 수동 흐름을 만든다 | 웹 화면과 작업 흐름을 연결한다 | 파일·데이터 처리 흐름을 설계한다 | 역할·자동화·운영 흐름을 통합한다 |
| C4 컨텍스트 | 단계별 짧은 요청을 사용한다 | 입력값에 따라 프롬프트를 조립한다 | 자료 요약과 상태 패킷을 관리한다 | 장기 프로젝트의 결정·변경 이력을 관리한다 |
| C5 결과물 | 재사용 가능한 미니 에이전트를 만든다 | 배포 가능한 웹 도구를 만든다 | 자료 연결형 기능을 만든다 | 테스트·배포 가능한 시스템을 만든다 |
| C6 검증 | 3개 사례로 확인한다 | 사용자 테스트와 예외 처리를 수행한다 | 자료 오류·환각·출처를 검증한다 | 자동 검사와 운영 지표를 관리한다 |
| C7 배포 | 공유 문서나 패키지를 제공한다 | GitHub Pages에 배포한다 | 동적 배포 또는 데이터 패키지를 제공한다 | Release와 변경 기록을 운영한다 |
| C8 책임·개선 | 기본 위험 체크리스트를 사용한다 | 사용 안내와 제한을 표시한다 | 개인정보·권한·데이터 정책을 적용한다 | 승인 체계와 지속 개선 절차를 운영한다 |

## 4. 공통 평가 수준

각 역량은 4단계로 평가한다.

| 수준 | 설명 |
|---|---|
| 1 시작 | 예시를 따라 일부 수행했으나 핵심 산출물이나 근거가 부족하다 |
| 2 수행 | 제공된 구조를 사용해 필수 과정을 완료한다 |
| 3 독립 | 새로운 주제에 맞게 구조를 수정하고 오류를 스스로 검토한다 |
| 4 전이 | 다른 사람에게 적용·설명하고 새로운 환경에서도 체계를 재구성한다 |

## 5. 평가 원칙

1. 최종 화면의 화려함보다 과정 산출물과 검증 기록을 우선한다.
2. AI가 생성한 문장의 품질만 평가하지 않는다.
3. 모든 레벨에서 C1, C3, C6, C8은 필수 통과 역량이다.
4. LEVEL 2부터 C7 배포·재사용을 필수 통과 역량으로 둔다.
5. LEVEL 3부터 C2 자료·근거 활용에서 출처와 오류 처리 기준을 강화한다.
6. LEVEL 4에서는 개인 완성도뿐 아니라 협업, 변경 관리와 운영 지속성을 평가한다.

## 6. 공통 루브릭 구조

각 프로젝트는 다음 8개 항목을 1~4수준으로 평가한다.

- 문제 정의
- 자료와 출처
- 작업 흐름
- 컨텍스트 관리
- 결과물 사용성
- 테스트와 검증
- 배포와 재사용
- 책임과 개선

점수 합계는 참고 자료로 사용하며, 필수 역량 미통과를 단순 총점으로 상쇄하지 않는다.

## 7. 포트폴리오 증거

학습자는 다음 증거를 제출한다.

- 프로젝트 브리프
- 자료 및 출처 기록
- 작업 흐름도
- 단계별 컨텍스트 패킷 또는 프롬프트 기록
- 최종 산출물
- 테스트 기록
- 배포 또는 공유 정보
- 개정 전후 비교와 회고
