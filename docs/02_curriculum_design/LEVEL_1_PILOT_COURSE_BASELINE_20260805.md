# LEVEL 1 시범 과정 기준안

- 작성일: 2026-08-05
- 승인일: 2026-08-07
- 단계: STAGE 02
- 상태: DECIDED
- 과정명: 근거 기반 수업 프로젝트 설계 미니 에이전트
- 권장 대상: 초·중등 교사 및 교육 실무자
- 총 수업 시간: 180분
- 기본 도구: 채팅형 AI + 통합 교육포털

## 1. 과정 목적

이 과정은 한 번의 프롬프트로 수업안을 생성하는 활동이 아니다. 학습자가 교육 문제를 정의하고, 근거 자료를 비교하고, 단계형 작업 구조를 설계하며, 서로 다른 입력으로 결과를 검증하는 작은 에이전트를 완성하는 과정이다.

## 2. 최종 결과물

수업 종료 시 학습자는 다음 여섯 가지를 하나의 재사용 패키지로 가진다.

1. 교육 문제 정의서
2. 출처가 기록된 근거 자료 3건 이상
3. 자료 비교표
4. 입력·작업 단계·출력·검증 기준을 가진 에이전트 카드
5. 정상·경계·실패 입력을 사용한 테스트 기록 3건
6. 다른 사람이 사용할 수 있는 공유용 미니 에이전트 패키지

## 3. 학습 목표

학습자는 다음을 수행할 수 있어야 한다.

- 해결할 교육 문제와 사용자를 한 문장으로 정의한다.
- 사실 자료와 AI 생성 결과를 구분한다.
- 자료를 공통 기준으로 비교한다.
- 복잡한 요청을 4~6개의 작업 단계로 나눈다.
- 입력 형식, 출력 형식과 검증 기준을 명시한다.
- 서로 다른 입력을 사용해 에이전트의 한계를 찾는다.
- 결과를 다른 사람이 재사용할 수 있는 형태로 정리한다.

## 4. 180분 표준 흐름

| 구간 | 시간 | 생명주기 | 핵심 활동 | 필수 산출물 |
|---|---:|---|---|---|
| 시작 | 15분 | 체험 | 나쁜 단일 프롬프트와 단계형 에이전트 비교 | 차이 기록 |
| 1 | 25분 | DEFINE | 사용자·문제·제약·성공 조건 정의 | 프로젝트 브리프 |
| 2 | 30분 | COLLECT + STRUCTURE | 자료 3건 비교, 필요한 입력과 처리 단계 결정 | 자료 비교표·작업 흐름 |
| 3 | 45분 | BUILD | 에이전트 카드와 단계별 채팅 명령 구성 | 에이전트 초안 |
| 4 | 30분 | TEST | 정상·경계·실패 사례 실행 및 오류 기록 | 테스트 기록 3건 |
| 5 | 20분 | PUBLISH | 사용 안내, 복사용 패키지와 상태 스냅샷 작성 | 공유 패키지 |
| 마무리 | 15분 | IMPROVE | 동료 검토와 1회 개정 | 개선 기록 |

## 5. 예시 따라하기와 자유도

### 공통으로 고정하는 70%

- 프로젝트 생명주기
- 입력·처리·출력·검증 구조
- 자료 비교표 형식
- 테스트 3종
- 공유 패키지 형식
- 개인정보·저작권·출처 점검

### 학습자가 선택하는 20%

- 교과와 학년
- 해결하려는 수업 문제
- 근거 자료 유형
- 최종 출력 형식
- 평가 또는 활동 방식

### 자유 설계 10%

- 추가 작업 단계
- 고유한 질문 방식
- 선택형 출력
- 새로운 검증 기준

## 6. 기준 예시

기준 예시는 `초등학교 고학년의 과학 탐구 활동 설계`로 한다.

에이전트는 다음 작업을 수행한다.

1. 수업 대상과 문제 확인
2. 제공 자료의 출처·핵심 주장·적용 가능성 분석
3. 자료 간 공통점과 충돌점 비교
4. 수업 목표와 활동 흐름 설계
5. 근거가 부족한 항목 표시
6. 교사가 확인할 최종 점검표 출력

학습자는 교과, 학년, 교육 문제와 최종 결과물 형식을 바꾸어 서로 다른 결과물을 만든다.

## 7. 에이전트의 최소 구조

- 역할: 무엇을 돕는가
- 사용자: 누가 사용하는가
- 입력: 사용자가 무엇을 제공해야 하는가
- 단계: 4단계 이상의 처리 과정
- 근거: 어떤 자료를 사용하며 어떻게 표시하는가
- 출력: 결과 형식과 필수 항목
- 검증: 결과를 검사하는 기준
- 중단: 근거 부족·개인정보·범위 초과 시 행동
- 수정: 피드백을 반영하는 방법

## 8. 테스트 기준

### 정상 사례

모든 필수 입력과 충분한 근거 자료가 제공된 경우다.

### 경계 사례

시간, 대상, 자료가 불충분하거나 조건이 서로 충돌하는 경우다.

### 실패 사례

개인정보, 존재하지 않는 출처, 과도한 범위 또는 답할 근거가 없는 입력이다.

에이전트는 실패 사례에서 그럴듯한 답을 꾸미지 않고 부족한 정보와 필요한 조치를 표시해야 한다.

## 9. 수업 운영 원칙

- 검색이 불가능한 환경을 위해 교사가 기준 자료 묶음을 제공한다.
- 검색 가능한 환경에서도 출처가 확인되지 않는 요약문은 근거로 인정하지 않는다.
- 채팅을 길게 이어가기보다 단계별 Context Packet을 사용한다.
- 최종 결과물보다 중간 산출물과 수정 기록을 평가한다.
- 학습자가 자신의 에이전트 구조를 2분 안에 설명할 수 있어야 한다.

## 10. 완료 게이트

다음 항목을 모두 충족해야 LEVEL 1 완료로 인정한다.

- 실제 사용자와 문제가 명시되었다.
- 근거 자료 3건 이상과 출처가 기록되었다.
- 작업 단계가 4단계 이상이다.
- 입력과 출력 형식이 명시되었다.
- 검증 기준과 중단 조건이 있다.
- 테스트 3건과 수정 기록이 있다.
- 다른 사람이 설명 없이 사용할 수 있는 공유 패키지가 있다.
