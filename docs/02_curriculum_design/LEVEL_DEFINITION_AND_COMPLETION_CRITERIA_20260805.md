# LEVEL 정의와 완료 기준

- 작성일: 2026-08-05
- 단계: STAGE 01
- 상태: PROPOSED_FOR_APPROVAL

## 1. 레벨 구분 원칙

레벨은 코드의 양이나 특정 AI 도구의 사용 여부로 구분하지 않는다. 다음 네 가지 책임 범위가 커지는 정도로 구분한다.

1. 작업 흐름의 자율성
2. 연결하는 자료와 시스템의 범위
3. 배포와 재사용 책임
4. 테스트와 운영 지속성

## 2. LEVEL 1: 채팅형 미니 에이전트

### 정의

학습자가 채팅형 AI와 수동으로 상호작용하면서 입력, 단계별 처리, 출력과 검증 기준을 가진 작은 작업 시스템을 설계한다.

### 권장 시간

3시간

### 허용되는 구현

- 채팅 프롬프트 묶음
- 단계별 에이전트 카드
- 웹포털에서 조립한 프롬프트 패키지
- 문서 또는 Markdown 기반 사용 설명서

### 필수 산출물

- 문제·사용자·제한 조건이 포함된 프로젝트 브리프
- 출처가 있는 자료 3건 이상 또는 제공 자료 묶음
- 3단계 이상의 작업 흐름
- 입력 형식과 출력 형식
- 자기 검토 또는 사람 검토 기준
- 서로 다른 테스트 입력 3건
- 재사용 가능한 공유 패키지

### 완료 기준

- 다른 사람이 5분 안에 사용을 시작할 수 있다.
- 입력이 달라지면 결과도 의미 있게 달라진다.
- 한 번의 거대한 프롬프트가 아니라 단계형 작업으로 구성된다.
- 최소 1개의 실패 사례를 발견하고 수정한다.
- 자료와 AI 생성 결과를 구분한다.

### LEVEL 1이 아닌 것

- 한 문장으로 앱이나 수업안을 생성하고 종료한 활동
- 테스트나 출처 없이 프롬프트만 모은 자료
- 사용자와 목적이 정의되지 않은 범용 챗봇

## 3. LEVEL 2: 배포형 웹 에이전트

### 정의

학습자가 제공된 웹 템플릿을 수정하여 사용자가 브라우저에서 입력하고 단계별 결과를 얻거나 AI 전달문을 생성할 수 있는 도구를 만들고 배포한다.

### 권장 시간

4~6시간

### 기본 기술 범위

- HTML, CSS, JavaScript 또는 검증된 정적 사이트 템플릿
- 브라우저 로컬 저장
- 입력에 따른 프롬프트 조립
- 결과 복사·저장·내보내기
- GitHub 저장과 GitHub Pages 배포

핵심 과정은 API 키 없이 작동해야 한다. 실제 AI 호출은 선택형 확장으로 둔다.

### 필수 산출물

- 사용자 흐름도
- 화면별 입력·출력 정의
- 동작하는 웹 도구
- 사용 안내와 제한 사항
- 정상·경계·오류 테스트 기록
- GitHub 저장소 내 코드와 문서
- GitHub Pages 배포 주소

### 완료 기준

- 처음 사용하는 사람이 안내에 따라 작업을 완료할 수 있다.
- 최소 2개 이상의 사용자 선택이 결과에 영향을 준다.
- 입력 오류 또는 빈 입력을 처리한다.
- 결과를 복사하거나 파일로 내보낼 수 있다.
- 배포 주소에서 새로고침 후에도 핵심 기능이 작동한다.

### LEVEL 2가 아닌 것

- 정적인 설명 페이지
- 디자인만 있고 실제 입력과 결과 흐름이 없는 화면
- 로컬에서만 우연히 작동하고 배포 검증이 되지 않은 프로젝트

## 4. LEVEL 3: 자료 연결형 에이전트

### 정의

학습자가 파일, 공개 데이터, 검색 결과, API 또는 읽기 전용 MCP를 연결하여 근거가 추적 가능한 결과를 생성하는 시스템을 설계한다.

### 권장 시간

8~12시간

### 필수 산출물

- 데이터 출처와 사용 조건
- 입력 데이터 형식 또는 스키마
- 자료 정제·분류·분석 흐름
- 출처가 연결된 결과물
- 누락·오류·오래된 자료 처리 규칙
- 개인정보와 권한 점검
- 데이터 및 기능 테스트 기록
- 배포 또는 실행 패키지

### 완료 기준

- 생성 결과의 주요 주장과 사용 자료를 연결할 수 있다.
- 잘못된 형식, 빈 자료와 중복 자료를 처리한다.
- 최신성이 중요한 자료는 기준 날짜를 표시한다.
- 비밀키와 개인정보를 저장소에 포함하지 않는다.
- MCP는 읽기 전용 연결부터 사용한다.

### LEVEL 3가 아닌 것

- 출처 없이 웹 검색 결과를 요약하는 활동
- 파일을 업로드했지만 실제 처리 흐름이 정의되지 않은 활동
- 개인정보나 API 키를 코드에 직접 저장한 프로젝트

## 5. LEVEL 4: 운영형 장기 프로젝트

### 정의

학습자가 저장소, 역할, 작업 목록, 테스트, 배포, 변경 기록과 운영 지표를 갖춘 장기 프로젝트를 수행한다.

### 권장 시간

15시간 이상 또는 3~6주 프로젝트

### 필수 산출물

- 프로젝트 헌장과 범위
- 요구사항과 백로그
- 역할·권한·승인 기준
- 저장소와 브랜치 운영 규칙
- 테스트 계획과 결과
- 배포 및 복구 절차
- Release와 변경 기록
- 운영 지표와 개선 기록
- 최종 핸드오프

### 완료 기준

- 다른 작업자가 문서만으로 프로젝트를 이어갈 수 있다.
- 변경 전후를 Git 기록으로 추적할 수 있다.
- 실패 시 복구 또는 되돌리기 절차가 있다.
- 사용자 피드백이나 운영 데이터를 다음 버전에 반영한다.
- 자동화가 사람의 승인 범위를 침범하지 않는다.

### LEVEL 4가 아닌 것

- 기능이 많지만 저장소와 문서가 없는 앱
- 한 사람이 한 번 제작하고 종료한 프로토타입
- 테스트와 운영 책임이 정의되지 않은 에이전트

## 6. 레벨 이동 게이트

| 이동 | 통과 조건 |
|---|---|
| L1 → L2 | 작업 흐름, 입력·출력, 테스트 기준을 설명할 수 있다 |
| L2 → L3 | 배포된 웹 도구와 GitHub 기록이 있고 자료 연결 필요성을 설명할 수 있다 |
| L3 → L4 | 출처·데이터 오류·권한을 처리하며 운영 범위를 정의할 수 있다 |

## 7. 공통 실패 기준

다음 중 하나라도 해당하면 해당 레벨을 완료한 것으로 보지 않는다.

- 필수 산출물 중 하나 이상이 없다.
- 테스트 기록이 없다.
- 출처 또는 데이터 사용 근거가 필요한데 기록하지 않았다.
- 다른 사용자가 실행할 수 없다.
- 개인정보, 비밀키 또는 저작권 위험을 방치했다.
- AI 생성 결과를 사람의 검토 없이 최종 결과로 확정했다.
