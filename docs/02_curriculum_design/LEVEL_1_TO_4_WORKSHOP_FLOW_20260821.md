# LEVEL 1~4 워크숍 운영 플로우 (2026-08-21)

## 상태와 적용 범위

이 문서는 기존의 LEVEL 1 대화봇 중심, LEVEL 2 배포형 웹 도구 중심 설명을 대체하는 **현재 포털 개편 기준**이다. 네 LEVEL은 선수·연계 과정이 아니라 각각 독립적으로 운영한다. 학습자는 자신의 경험과 수업 시간에 맞는 LEVEL 하나를 선택해 완성 결과물을 만든다.

기존 실험형 모듈은 `portal/legacy/`에서 참고 자료로 보존한다. 삭제하지 않으며, 현재 과정의 첫 화면과 기본 진입 경로에서는 제외한다.

## 공통 수업 방식: 두 창, 한 번에 한 일

수업은 학습 페이지와 외부 생성형 AI(Gemini, ChatGPT 등)를 나란히 연다. 학습 페이지가 AI를 흉내 내거나, 긴 설명과 빈 입력칸을 반복하지 않는다.

모든 실습 화면은 다음의 짧은 순서를 사용한다.

1. **오늘 만들 한 가지**: 예시와 통과 기준을 확인한다.
2. **AI에 요청하기**: 복사 가능한 프롬프트를 AI에 보낸다.
3. **실행해 보기**: 브라우저 또는 휴대폰에서 실제 결과를 확인한다.
4. **한 점만 고치기**: 관찰한 문제를 핀포인트 수정 요청으로 바꾼다.

프롬프트의 기본 형식은 다음과 같다.

```text
[현재 단계] [만들 목표] [사용자와 입력] [원하는 결과]
[바꾸지 말 것] [이번에 확인할 통과 기준] [출력 형식]
```

수정 프롬프트는 이유를 길게 쓰지 않고 아래 다섯 항목만 사용한다.

```text
현재 결과 / 관찰한 문제 / 기대하는 변화 / 바꾸지 말 것 / 전체 코드 출력
```

## LEVEL 1 — 나의 생활 PWA

| 항목 | 기준 |
| --- | --- |
| 권장 시간 | 3~4시간 |
| 핵심 경험 | AI와 함께 작은 웹앱을 만들고, 휴대폰에 설치한다. |
| 기술 범위 | HTML, CSS, JavaScript, localStorage, PWA manifest, service worker, GitHub Pages |
| 사용 금지 | 외부 API, 비밀키, 데이터베이스 |
| 완성 기준 | 모바일에서 쓸 수 있고, 새로고침 후 기록이 남으며, GitHub Pages에서 설치 안내가 가능한 앱 |

따라 하기 예시는 셋 중 하나를 선택한다.

1. **시험 집중 플래너**: 과목·가능 시간·시험일을 바탕으로 오늘 할 일을 정리한다.
2. **수행평가·모둠 프로젝트 보드**: 마감일·준비물·역할을 기록하고 완료를 표시한다.
3. **나의 진로 선택 기준 카드**: 관심·강점·가치를 카드로 정리하고 탐색 주제를 선택한다.

PWA는 단일 HTML 파일만으로 완성되지 않는다. 최소 `index.html`, `manifest.webmanifest`, `service-worker.js`, 아이콘 파일을 묶어 GitHub Pages에 배포한다. 로컬 파일을 더블클릭해서는 설치 기능을 검증할 수 없으므로 HTTPS 배포 주소에서 휴대폰 테스트를 한다.

## LEVEL 2 — 나의 문제 해결 에이전트

| 항목 | 기준 |
| --- | --- |
| 권장 시간 | 6~8시간 |
| 핵심 경험 | 한 번의 답변이 아니라 입력→질문→AI 요청→판단→실행 계획의 흐름을 설계한다. |
| 기술 범위 | 정적 웹앱, localStorage, 프롬프트 생성, 결과 붙여넣기, 체크리스트·내보내기 |
| 사용 금지 | AI API, 외부 API, 자동으로 결정을 대신하는 기능 |
| 완성 기준 | 사용자가 자신의 입력과 AI 결과를 구분해 기록하고, 다음 행동을 정할 수 있는 웹 워크플로 |

추천 주제는 수행평가 준비 코치, 진로 탐색 계획 도우미, 학교 행사 준비 에이전트다. 앱은 AI의 답을 꾸며 내지 않는다. 사용자가 외부 AI의 답을 붙여넣고, 앱은 그 답을 자신의 계획·질문·체크리스트로 정리하는 역할을 한다.

## LEVEL 3 — 부산 생활 데이터 에이전트

| 항목 | 기준 |
| --- | --- |
| 권장 시간 | 10~12시간 |
| 핵심 경험 | 외부 데이터의 요청·응답·출처·갱신·오류를 사용자 경험으로 바꾼다. |
| 기술 범위 | 공공데이터 API, 교사 관리 중계 주소, 데이터 변환, 상태 표시 |
| 완성 기준 | 정상·빈 결과·잘못된 입력·네트워크 오류를 구분하고, 출처와 마지막 갱신 시각을 표시하는 앱 |

공통 프로젝트는 **부산 등굣길 버스 도우미**다. 학생은 버스 번호, 정류장명 또는 ARS 번호로 노선·정류장·도착 예정 정보를 찾는다. 지도나 현재 위치 권한은 심화 과제로 남긴다. 선택 심화는 **부산에서 찾는 책**(도서 검색과 소장 도서관 탐색)이다.

부산버스정보시스템 API는 정류소, 노선, 도착 예정 및 실시간 위치 정보를 제공한다. API 키는 GitHub Pages나 학생 HTML에 절대 넣지 않는다. 교사가 준비한 중계 서버 또는 수업용 안전한 요청 환경을 제공하며, 키의 소유자·호출 한도·오류 대응을 수업 전에 확인한다.

## LEVEL 4 — AI 모델 활용 서비스

| 항목 | 기준 |
| --- | --- |
| 권장 시간 | 16시간 이상 |
| 핵심 경험 | 실제 AI 모델을 서비스에 연결하고, 안전·비용·개인정보·운영 책임을 함께 설계한다. |
| 기술 범위 | AI API, 서버 환경 변수, 자료 검색 또는 RAG, 사용자 검토, 운영 로그 |
| 완성 기준 | API 키가 브라우저에 노출되지 않고, 근거·한계·위험 질문 처리·비용 한도를 갖춘 서비스 |

예시는 자료 기반 질문 도우미, 개인화 학습 지원 서비스, 학교 문제 해결 AI 서비스다. 철학자 자료를 바탕으로 응답하는 서비스는 이 LEVEL의 적절한 심화 사례다.

## 텔레그램 알림봇의 위치

<!-- TELEGRAM_GUIDE_ONLY: live bot implementation is intentionally out of the default student workflow. -->

텔레그램은 기본 실습이 아닌 **심화 안내 자료**다. 봇 토큰, 수신자 권한, 개인정보, 외부 메시지 발송, 지속 실행이 필요하기 때문이다.

학습 자료에는 데이터 흐름, 토큰을 프런트엔드에 넣으면 안 되는 이유, 수신 동의, 민감정보 금지, 오류·발송량 제한을 포함한다. 실제 알림 발송 구현은 Level 4의 교사 관리 환경에서만 선택적으로 다룬다.

## 포털 교체 및 보관 정책

- `portal/index.html`은 새 4레벨 선택 화면으로 사용한다.
- `portal/legacy/`는 기존 Level 1·2 실험형 모듈의 안내·접근 경로다.
- 기존 모듈의 파일과 Git 이력은 삭제하지 않는다.
- 새 Level별 워크숍 페이지는 이 문서의 공통 화면 순서와 결과물 기준에 맞춰 순차적으로 교체한다.
