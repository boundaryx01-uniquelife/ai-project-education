# 토큰 절약형 컨텍스트 패킷 표준

- 작성일: 2026-08-05
- 단계: STAGE 01
- 상태: PROPOSED_FOR_APPROVAL

## 1. 목적

긴 대화 전체를 반복해서 전달하지 않고도 AI가 현재 프로젝트의 맥락, 확정 결정과 이번 작업을 정확히 이해하도록 하는 최소 정보 단위이다.

컨텍스트 패킷은 특정 AI 제품에 종속되지 않으며 ChatGPT, Claude, Codex, Claude Code와 Antigravity용 어댑터에서 공통으로 사용한다.

## 2. 기본 원칙

1. 하나의 패킷에는 하나의 단계와 하나의 주 작업만 넣는다.
2. 이전 대화 전체가 아니라 확정된 결정만 전달한다.
3. 원문 자료는 필요한 부분만 인용하고 출처 번호를 남긴다.
4. 결과 형식과 검증 기준을 요청문 안에 포함한다.
5. 단계 종료 시 다음 대화에서 사용할 상태 스냅샷을 만든다.
6. 불필요한 역할극, 반복 설명과 장황한 예시는 제거한다.

## 3. 표준 패킷

```markdown
# PROJECT CONTEXT PACKET

## PROJECT
- 프로젝트명:
- 최종 목적:
- 대상 사용자:

## CURRENT STAGE
- 현재 단계:
- 이번 단계의 목적:

## FIXED DECISIONS
- 이미 확정되어 변경하지 않을 내용:

## INPUTS
- 이번 작업에서 사용할 자료:
- 출처 또는 파일 식별자:

## TASK
- 이번에 수행할 단일 작업:

## OUTPUT
- 필요한 결과 형식:
- 길이 또는 파일 구조:

## CONSTRAINTS
- 금지 사항:
- 시간·도구·개인정보 제한:

## VALIDATION
- 완료 조건:
- 반드시 확인할 실패 사례:

## STOP CONDITION
- 임의로 다음 단계까지 진행하지 말고 멈출 지점:
```

## 4. 단계 종료 상태 스냅샷

```markdown
# STATE SNAPSHOT

## COMPLETED
- 이번 단계에서 완료한 것:

## DECIDED
- 확정된 결정:

## ARTIFACTS
- 생성된 파일·링크·결과물:

## OPEN
- 해결되지 않은 문제:

## NEXT
- 다음 단계에서 처음 수행할 작업:

## DO NOT CHANGE
- 다음 작업자가 임의로 바꾸면 안 되는 항목:
```

## 5. 레벨별 사용 방식

### LEVEL 1

웹포털이 입력 양식을 받아 패킷을 자동 조립한다. 학습자는 패킷을 채팅 AI에 복사하고 결과를 포털에 기록한다.

### LEVEL 2

웹 도구가 사용자 입력을 패킷 형식으로 조립하고 복사·내보내기를 제공한다. 이전 단계 상태는 브라우저 로컬 저장 또는 파일로 유지한다.

### LEVEL 3

자료의 원문 전체 대신 파일명, 출처 ID, 요약과 필요한 발췌를 사용한다. 데이터 스키마와 기준 날짜를 명시한다.

### LEVEL 4

상태 스냅샷을 저장소 문서, Issue, 작업 지시서와 핸드오프에 연결한다. 장기 프로젝트에서는 최신 기준 문서의 우선순위를 명시한다.

## 6. 토큰 절약 규칙

- 공통 수업 설명과 예시는 AI에 매번 전달하지 않고 포털에 표시한다.
- `FIXED DECISIONS`는 핵심 결정 10개 이내를 기본으로 한다.
- 하나의 요청에서 산출물 종류를 과도하게 묶지 않는다.
- 이전 결과를 다시 사용할 때는 전체 원문 대신 상태 스냅샷을 우선한다.
- 대량 자료는 먼저 분류·요약한 뒤 필요한 부분만 다음 단계로 전달한다.
- 같은 내용의 한국어·영어 중복 전달을 피한다.

## 7. 품질 검사

패킷을 전달하기 전에 다음을 확인한다.

- 현재 단계와 작업이 하나로 좁혀졌는가?
- 확정 결정과 변경 가능한 항목이 구분되는가?
- 입력 자료의 출처를 찾을 수 있는가?
- 출력 형식이 명확한가?
- 완료 조건과 실패 사례가 있는가?
- AI가 임의로 다음 단계까지 확장하지 않도록 멈춤 조건이 있는가?

## 8. 교육적 의미

컨텍스트 패킷은 단순한 토큰 절약 도구가 아니다. 학습자가 문제와 자료를 구조화하고, AI에게 위임할 작업과 사람이 책임질 판단을 분리하는 핵심 교육 산출물이다.
