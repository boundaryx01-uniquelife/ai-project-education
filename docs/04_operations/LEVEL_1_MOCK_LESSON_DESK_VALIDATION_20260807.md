# LEVEL 1 간이 모의수업 데스크 검증

- 작성일: 2026-08-07
- 대상: `근거 기반 수업 프로젝트 설계 미니 에이전트`
- 검증 유형: DESK_SIMULATION
- 실제 수강생 참여: 없음
- 상태: READY_WITH_FIELD_VALIDATION_REQUIRED

## 1. 목적

STAGE 02에서 확정한 180분 LEVEL 1 과정이 실제 수업에서 무리 없이 작동할 가능성이 있는지 문서와 산출물 흐름을 기준으로 점검한다.

이 검증은 실제 교사·학습자 참여 수업을 대체하지 않는다. 사람의 이해도, 실제 입력 속도와 장비·네트워크 문제는 `FIELD_VALIDATION_REQUIRED`로 남긴다.

## 2. 검증 기준

다음 흐름이 180분 안에 끊김 없이 이어져야 한다.

`체험 → DEFINE → COLLECT → STRUCTURE → BUILD → TEST → PUBLISH → IMPROVE`

필수 산출물은 다음과 같다.

1. 프로젝트 브리프
2. 출처가 기록된 자료 3건 이상
3. 자료 비교 결과
4. 에이전트 카드
5. 정상·경계·실패 테스트 기록
6. 수정 기록
7. 공유 가능한 Markdown 패키지

## 3. 시간 시뮬레이션

| 구간 | 기준 시간 | 데스크 판정 | 주의점 |
|---|---:|---|---|
| 공통 체험 | 15분 | PASS | 예시 비교 화면이 즉시 준비되어야 함 |
| DEFINE | 25분 | PASS | 자유 서술보다 짧은 필드 입력이 적합 |
| COLLECT + STRUCTURE | 30분 | CONDITIONAL | 실시간 검색까지 포함하면 과부하 가능 |
| BUILD | 45분 | PASS | 에이전트 카드 자동 조립이 필요 |
| TEST | 30분 | PASS | 정상·경계·실패 유형을 포털이 미리 구분해야 함 |
| PUBLISH | 20분 | PASS | Markdown 자동 조립이 전제 |
| IMPROVE | 15분 | PASS | 피드백 입력을 3문장 수준으로 제한 |

## 4. 핵심 발견

### F01. COLLECT 구간의 시간 위험

30분 안에 자료 탐색, 출처 검증, 비교와 STRUCTURE까지 모두 수행하면 초보자는 시간이 부족할 가능성이 높다.

**조치:**

- 기본 수업에서는 교사가 검증 가능한 기준 자료 묶음을 제공한다.
- 웹 검색은 선택 활동으로 둔다.
- 자료 입력 필드는 S1, S2, S3로 고정하고 최소 정보만 요구한다.

### F02. Context Packet의 개념 부담

초보 학습자에게 Context Packet이라는 용어 자체가 학습 목표보다 앞에 나올 위험이 있다.

**조치:**

- 화면 표기는 `AI에게 보낼 작업 묶음`을 우선 사용한다.
- 보조 설명에서만 `Context Packet`이라는 정식 용어를 병기한다.
- 사용자가 직접 문법을 작성하지 않고 입력값으로 자동 조립한다.

### F03. State Snapshot의 작성 부담

매 단계마다 학습자가 별도의 요약문을 작성하면 토큰 절약을 배우기 전에 반복 작업으로 인식할 수 있다.

**조치:**

- 포털이 현재 입력값을 기준으로 State Snapshot 초안을 자동 생성한다.
- 학습자는 `확정 결정`, `남은 문제`, `다음 입력`만 수정한다.

### F04. TEST 구간의 추상성

정상·경계·실패라는 분류만 제시하면 초보 학습자가 테스트 입력을 만들지 못할 수 있다.

**조치:**

- 각 탭에 한 개의 기준 예시를 제공한다.
- 실패 테스트는 `가짜 출처`, `개인정보`, `근거 부족` 중 하나를 기본 선택하도록 한다.
- 테스트 결과는 `예상 → 실제 → 문제 → 수정` 4칸으로 제한한다.

### F05. 산출물 과다 노출

7단계의 모든 문서를 동시에 보여주면 수업이 문서 작성 실습처럼 느껴질 수 있다.

**조치:**

- 현재 단계 산출물만 화면에 강조한다.
- 최종 패키지는 뒤에서 자동 합성한다.
- 진행률은 산출물 개수가 아니라 7단계 생명주기로 표시한다.

### F06. 자유도 관리

LEVEL 1에서 주제를 완전히 자유롭게 하면 DEFINE 단계에 시간이 소모될 가능성이 높다.

**조치:**

초기 포털에서 다음 세 가지 시작 방식을 제공한다.

1. 기준 예시 그대로 체험
2. 교과·학년·문제만 변경
3. 직접 주제 입력

기본값은 2번으로 한다.

## 5. 포털 구현에 반영할 우선순위

### MUST

- 7단계 진행 표시
- 자동 저장
- 단계별 최소 입력 필드
- 기준 예시와 잘못된 예시
- Context Packet 자동 조립
- State Snapshot 자동 조립
- 정상·경계·실패 테스트 템플릿
- Markdown 전체 패키지 내보내기
- 전체 데이터 삭제
- 개인정보 입력 금지 안내

### SHOULD

- 교사용 시간 안내
- 단계별 완료 체크
- 입력 누락 경고
- 이전 단계 수정 후 이후 산출물 재생성 안내
- 복사 성공 피드백

### LATER

- JSON 내보내기
- 인쇄용 HTML
- 주제 프리셋 추가

## 6. 데스크 검증 판정

**READY_WITH_FIELD_VALIDATION_REQUIRED**

현재 설계는 포털 MVP 구현에 들어갈 수 있다. 다만 다음은 실제 소규모 수업 이후 확정해야 한다.

- 실제 DEFINE 평균 소요시간
- 자료 3건 입력의 체감 부담
- Context Packet 이해 여부
- 테스트 3종 완주율
- 모바일·학교 PC 환경의 입력 편의성
- 루브릭의 평가자 간 일치도

- 공통 7단계 생명주기
- LEVEL 1 180분 구조
- 자료 3건 이상
- 정상·경계·실패 테스트 3종
