# 문서 및 버전 관리 표준

- 작성일: 2026-08-05
- 상태: DECIDED

## 문서 상태

- `DRAFT`: 작성 중
- `PROPOSED`: 검토 요청
- `DECIDED`: 승인된 기준
- `SUPERSEDED`: 최신 문서로 대체됨
- `ARCHIVED`: 기록용 보관

## 파일명

기본 형식은 다음과 같다.

`<DOCUMENT_NAME>_YYYYMMDD.md`

같은 날짜에 내용을 개정하면 `_R02`, `_R03` 순으로 붙인다.

## 단계별 필수 문서

각 STAGE는 최소한 다음 문서를 남긴다.

1. 설계 또는 기준 문서
2. 결정 기록
3. 검증 결과
4. 다음 단계 핸드오프

## 우선순위

문서 내용이 충돌하면 다음 순서를 적용한다.

1. 최신 날짜의 `DECIDED` 문서
2. 같은 날짜에서는 가장 높은 개정 번호
3. 단계별 최종 핸드오프
4. 이전 단계 문서
5. 채팅 기록과 임시 메모

## Git 규칙

- 한 커밋에는 하나의 명확한 변경 목적을 담는다.
- 문서 변경은 `docs/<topic>` 브랜치를 사용한다.
- 기능 변경은 `feature/<topic>` 브랜치를 사용한다.
- `main`은 승인된 기준과 배포 가능한 상태를 유지한다.
- 정식 교육 버전은 `v0.1.0`, `v0.2.0`, `v1.0.0` 형식으로 태그한다.
